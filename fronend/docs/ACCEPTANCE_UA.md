# Приймання після розміщення

- [ ] /health повертає ok:true; вимкнений ноутбук не впливає на API/вебадресу.
- [ ] Статична вебверсія відкривається на Safari iPhone і Chrome, пряме /auth/callback не дає 404.
- [ ] A і B зареєстровані на різні email, справжні листи доходять; код неправильний/прострочений/використаний відхиляється.
- [ ] Вхід, вихід, перезапуск, відновлення, зміна пароля перевірені на двох пристроях.
- [ ] Публічний профіль А видимий B, телефон А ніде не видається B.
- [ ] Нове оголошення чекає схвалення; після approved B його бачить; B не може змінити оголошення А.
- [ ] Фото профілю й оголошень не губляться після рестарту API.
- [ ] Чат А/B: текст, фото, оновлення протягом приблизно 10 секунд при активному застосунку.
- [ ] C не бачить чат і не може отримати ticket на його фото; вихід відкликає ticket.
- [ ] Блокування працює в обох напрямках відправлення.
- [ ] Скарга зберігається для адміністратора, перегляд і реакція організовані.
- [ ] Видалення тестового акаунта прибирає дані/фото й відкликає сесії. Перевірити також під час паралельного надсилання повідомлень.
- [ ] API після простою пробуджується; інтерфейс показує помилку/повтор без втрати введення.
- [ ] Google/Facebook перевірені власними тестерами після налаштування callback, включно зі скасуванням та відсутнім email.
- [ ] Умови, приватність, підтримка справжні й доступні; згоди на новини не ввімкнені автоматично.
- [ ] Клавіатура, прокручування, вибір фото, великі шрифти й малий екран перевірені на iPhone.
- [ ] Ліміти Atlas/Render/Resend та резервне копіювання перевірені перед відкритою бетою.
