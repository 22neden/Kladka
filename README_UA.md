# Kladka.UA v1.2 — Expo + Express + MongoDB

Повний проєкт із двома частинами. Expo залишається. Реальні дані тепер проходять через Express у MongoDB, Supabase для цієї версії не потрібен.

**Цей архів підготовлено для налаштування й тестування. Публічний frontend можна розмістити на Netlify, а backend — на Render.**

## Один зрозумілий запуск на Windows
Збережіть старий проєкт. Розпакуйте нову версію в нову папку. Нижче D:\KLADKA — приклад кореня: саме тут лежать package.json, render.yaml і папка apps з backend та frontend.

Перший раз:
```powershell
cd D:\KLADKA
npm.cmd run setup
npm.cmd run init-env
```
setup встановлює залежності обох частин за lockfile. init-env створює два .env, генерує AUTH_SECRET і не перезаписує наявні файли. Не повторюйте npm ci при кожному запуску.

Відкрийте apps/backend/.env:
- MONGODB_URI — ваш актуальний Atlas URI із назвою бази kladka (пароль, який надсилали в чат, замініть в Atlas).
- AUTH_SECRET — уже згенеровано init-env.
- TERMS_URL — справжня HTTPS-адреса ваших Умов. Без неї нова реєстрація закрита.
- MAIL_MODE=console лише для тесту на власному ноутбуці: код підтвердження/відновлення показується в терміналі сервера. Це не надсилання листів.

Відкрийте apps/frontend/.env:
- EXPO_PUBLIC_API_URL=http://localhost:3000 для вебперевірки на ноутбуці.
- EXPO_PUBLIC_TERMS_URL — той самий URL Умов.
- EXPO_PUBLIC_PRIVACY_URL, EXPO_PUBLIC_SUPPORT_EMAIL — ваші контакти/документи.

Термінал №1, корінь D:\KLADKA:
```powershell
npm.cmd run backend
```
Термінал №2, той самий корінь:
```powershell
npm.cmd run web
```
Для iPhone через Expo Go: в обох .env адреси API повинні містити IPv4 ноутбука замість localhost (наприклад http://192.168.0.103:3000, але перевірте свій IP командою ipconfig). У backend це PUBLIC_API_URL; у застосунку EXPO_PUBLIC_API_URL. Потім перезапустіть сервер і Expo:
```powershell
npm.cmd run frontend
```
Ноутбук і телефон мають бути в одній приватній мережі; Node.js дозволений брандмауером для приватних мереж. Спочатку відкрийте http://IP:3000/health у Safari. Для хмарного доступу використовуйте HTTPS; expo --tunnel не відкриває Express-порт 3000.

## Без ноутбука
Для backend і MongoDB виконайте docs/DEPLOY_RENDER_UA.md. Для frontend на Netlify виконайте docs/DEPLOY_NETLIFY_UA.md. Результат — дві адреси:
- https://ВАШ-API.onrender.com — бекенд;
- https://ВАШ-WEB.onrender.com — вебверсія застосунку для вас і друзів.
Після цього вебверсія працює незалежно від VS Code, а дані зберігаються в Atlas. Безкоштовний API Render може засинати; перший запит потребує часу. Це не обіцянка SLA 24/7.
Expo Go залишається для розробки. Для окремої встановленої iOS-збірки потрібен окремий етап підписування/поширення. Вебпосилання не є .ipa чи публікацією в App Store.

## Що перенесено
Email-вхід, реєстрація з кодом, відновлення/зміна пароля, сесії, профілі, приватні налаштування, оголошення, обране, чат, фото, скарги, блокування, видалення акаунта. Google/Facebook мають серверні OAuth-маршрути, але працюватимуть лише після налаштування власних провайдерів; живі входи ними не перевірені.
При порожньому EXPO_PUBLIC_API_URL зберігається локальний режим із позначеними прикладами. При налаштованому API збій сервера не переключає застосунок на вигадані дані.

## Що відрізняється від v1.1
- Чати оновлюються запитами кожні 10 секунд, поки застосунок активний. Це не push і не Supabase Realtime.
- Фото зберігаються в MongoDB, а не на тимчасовому диску Render: до 5 МБ/фото та 20 МБ/акаунт. Ліміт Atlas спільний для всіх даних; перед масштабуванням потрібне окреме сховище зображень.
- Нові оголошення чекають модерації. Дивіться docs/MONGODB_UA.md.
- Старі локальні дані залишаються локальними. Supabase-акаунти/дані автоматично не мігрують. Колекцію items зі старого тестового сервера не видалено, але новий каталог використовує kladka_listing.
- Для авторизації використовуються відкличні серверні сесії на 30 днів. Паролі хешуються scrypt; сирі паролі не зберігаються.

## Файли, які потрібні далі
- docs/DEPLOY_RENDER_UA.md — публікація крок за кроком.
- docs/DEPLOY_NETLIFY_UA.md — публікація Expo web на Netlify.
- docs/MONGODB_UA.md — Atlas, акаунти, OAuth, модерація, медіа.
- docs/TEST_REPORT.md — фактично виконані перевірки та обмеження.
- docs/ACCEPTANCE_UA.md — перевірка після розміщення.

## Перевірки
Із кореня:
```powershell
npm.cmd run typecheck
npm.cmd run lint
npm.cmd test
npm.cmd run test:remote
```
npm test: тести API з тестовим сховищем у пам’яті та доменні тести застосунку. test:remote: реальний експорт Expo → HTTP Express → тестове сховище. Жива MongoDB перевіряється окремо:
```powershell
cd apps/backend
npm.cmd run test:integration
```
Ця команда завантажує тестовий mongod, створює тимчасовий replica set та не використовує ваш MONGODB_URI. Перший запуск потребує інтернету. У середовищі підготовки mongod не зміг стартувати; цей тест тут не пройдено.
